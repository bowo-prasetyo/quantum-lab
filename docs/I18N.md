# Internationalization (I18n)

> Status: **Phase 5 under way**: Glass Qubit speaks English,
> **Bahasa Indonesia** and **日本語** (see [Languages](#languages)). Everything a learner
> reads or hears is translatable: 345 interface messages in `locales/`, and
> the lessons, Quantum Concepts and Help (about 7,800 words) in `content/`.
> The Indonesian and Japanese translations still need a review by a
> physics-literate speaker of each language.

## Goals

- A learner can use Glass Qubit in their own language, chosen automatically
  from the browser and changeable in the top bar.
- Nothing about the product's constraints changes: no build step, no back
  end, no new runtime dependency, and everything stays testable in Node.
- The physics stays exactly as correct in every language. The lesson checks
  and the simulator don't depend on language at all.

## Design

| File | Role |
|---|---|
| `i18n.js` | The core: current language, `t()` for messages, `formatNumber`, `formatPercent`, `formatList`, `capitalize`, choosing a language. Plain JavaScript, no DOM, no Vue, so unit tests and plain modules (`describe.js`, `lesson-checks.js`) can use it. |
| `locale.js` | Connects the core to the page: picks the start language, keeps `<html lang>` and `dir`, the title and description in step, saves the learner's choice, fires `localechange` so canvases redraw. Its Vue plugin gives every template `$t` and `$locale` and the `<i18n-t>` component, and makes every `t()` and format call depend on the language, so the page updates by itself when it changes. |
| `locales/en.js` | The interface in English, the source language: short messages by key. |
| `content/en.js` | The long-form text in English: the lessons' words, Quantum Concepts and Help (see [Content](#content)). |
| `content.js` | The content in the current language, with button and view names filled in: `lessonText(id)`, `partTitle`, `conceptsText`, `helpText`. |
| `locales/index.js` | The list of languages, each with its messages and content. |
| `locales/pseudo.js` | The pseudo-locale, a fake language for testing (below). |

### Choosing the language

In order, the first that the app supports:

1. `?lang=` in the address, e.g. `index.html?lang=de#/lab/1`. Handy for
   sharing and testing; the only way to choose the pseudo-locale.
2. The learner's earlier choice in the top bar (`glass-qubit-locale` in
   localStorage, like the theme).
3. The browser's languages (`navigator.languages`), in order of preference.
   An exact match wins; otherwise the same language in another region
   (`pt-PT` → `pt-BR`).
4. English.

Choosing in the top bar saves the choice and removes any `?lang=` from the
address, so the choice sticks on the next visit. The picker only appears
when there is more than one language to choose from.

### Messages

Flat objects of dotted keys, grouped by where they appear:

```js
'nav.lessons': 'Lessons',
'nav.lab': { one: '{count} qubit', other: '{count} qubits' },
```

- **Placeholders:** `{name}` is replaced by `params.name`:
  `$t('nav.lab', { count: 2 })`. Never build a sentence from pieces in code;
  the word order differs between languages. Put the whole sentence in one
  message with placeholders.
- **Plurals:** a message written as an object is a plural. `params.count`
  picks the form by the language's rules (`Intl.PluralRules`: `zero`, `one`,
  `two`, `few`, `many`, `other`). English needs `one` and `other`; Polish
  needs `one`, `few`, `many` and `other`; Japanese only `other`. Never write
  `n === 1 ? 'qubit' : 'qubits'` in code.
- **Fallback:** a key missing in `pt-BR` is looked for in `pt`, then
  English. A key missing everywhere shows on screen as the key itself, with a
  console warning.
- **Numbers:** placeholders are inserted as they are. Format numbers first
  (see [Numbers](#numbers)).
- **Lists:** `formatList(['X', 'H', 'Z'])` gives `X, H and Z` (English
  follows British rules, like the text), or the language's own way of
  joining a list. A plain comma list uses the `list.separator` message.
- **Markup:** a message may hold `**bold**`, `*emphasis*` and
  `[links](/lessons)`. Show it with `<i18n-t>` (below), never with
  `v-html`: the component builds Vue elements, so a translation can't inject
  HTML. Plain `t()` returns the markup as it is, so keep it out of messages
  used for `aria-label`s and announcements.
- **Button names in sentences** come from the button's own message, passed
  as a placeholder: "{measureAll} or {reset} makes it pure again" with
  `measureAll: $t('gates.measureAll')`. A translation then can't name a
  button differently from the button itself.

In a Vue template: `{{ $t('nav.lessons') }}`, or `:aria-label="$t('nav.home')"`.
In plain JavaScript: `import { t } from './i18n.js'`.

A message with markup, or with an element inside it:

```html
<i18n-t k="lab.intro" tag="p" :params="{ count: 4, first: '|00⟩', last: '|11⟩' }" />

<i18n-t k="density.caption" tag="p" :params="{ max }">
  <template #rho>ρ<sub>ij</sub></template>
</i18n-t>
```

`{name}` becomes the slot of that name if there is one, else `params.name`.

### Keeping messages in step with the code

Messages must not go stale when the language changes:

- Work text out when it is shown (in the template or a computed property),
  never once when something happens. Keep the facts as data and put them
  into words later: a single-qubit measurement is kept as `{ qubit, bit }`
  and shown with `measurementText()`; a lesson keeps the state it checked and
  works out the check results from it.
- The one exception is a screen-reader announcement, which is spoken once,
  in the language of the moment.
- Text drawn on a canvas is redrawn on `localechange`, like on `themechange`
  (`redrawOnResize` in `components/canvas-fit.js` does both).

`tests/messages.test.js` checks that every key the code names is in
`en.js` and that every message in it is used. Keys built from a variable,
such as `` t(`gate.${gate}`) ``, are listed there in `DYNAMIC`.

### Numbers

Every number a learner sees, in text, tables, `aria-label`s and on the
canvases, goes through `formatNumber` or `formatPercent`, so it uses the
language's decimal separator, maths included: `0,707 + 0,000i` in German.

- `formatNumber(0.7071, { digits: 3 })`: `0.707`, or `0,707` in German.
- `formatPercent(0.125)`: `12.5%`, or `12,5 %`. `{ fixed: true }` keeps the
  decimals (`50.0%`).
- `{ minus: true }` uses a real minus sign (−0.71), as the maths views do.
- Thousands are grouped only from five digits (`12,345` but `1000`), as is
  usual for numbers in science.
- Numbers round exactly as `toFixed` did, so English reads exactly as
  before (a unit test compares them on 20,000 values); only `-0` never
  appears.

Quantum notation stays as it is: |01⟩, gate names, `q0` in circuit steps,
`⟨XX⟩`, `Tr ρ²`.

### Not translated

- The name **Glass Qubit**, and gate names (H, X, CNOT…).
- Quantum notation: |0⟩, |10⟩, ρ, ⟨Z⟩. Qubit 0 is always the left digit,
  so this notation stays left to right even in a right-to-left language.
- Lesson ids, routes (`#/lab/2`) and saved data, so progress and saved
  states survive a change of language.
- Error messages from `engine.js`, which only developers see.

## Pseudo-locale

Open the app with `?lang=en-XA` (e.g.
`index.html?lang=en-XA#/lab/1`). Every translated message turns into
`⟦Ļéššöñš ~~~⟧`: still readable, but:

- any plain English left on screen **hasn't been made translatable yet**;
- the brackets show where text is **cut off**;
- the `~` make each message about a third **longer**, as German or
  Indonesian often are, to show layouts that break;
- numbers follow **German rules** (`0,707`, `50 %`), so a number still shown
  as `0.707` hasn't been formatted for the language.

It is generated from `en.js`, so it never needs updating, and it is never
chosen from the browser's languages or offered in the picker unless it is in
use.

## Content

The lessons, Quantum Concepts and Help are long text with structure, so
they live apart from the messages, in `content/en.js`:

- `parts`: each part's title.
- `lessons`, by lesson id: `title`, `goal`, `why`, `steps`, `question`,
  `options`, `result`. Everything else about a lesson (operations, checks,
  panels, the right answer) stays in `lessons.js`, the same in every
  language. Keep the options in the same order: `predict.answer` is an
  index into them.
- `concepts`: `title`, `intro`, and sections of `[term, text]` items.
- `help`: `title`, `intro`, and sections of blocks: `{ p }`, `{ ul }`, `{ ol }`.

Text may use the same markup as messages (`**bold**`, `*emphasis*`,
`[links](/route)`) and is shown with `<i18n-t :text="...">`.

**Button and view names are placeholders**, filled in from the interface's
own messages: "Press {measureAll}." reads "Press Measure all." in English
and uses the translated button label in any other language, so a lesson can
never name a button differently from the button itself. `BUTTONS` in
`content.js` lists every placeholder and its message: buttons, checkboxes,
noise kinds, the top bar's labels, and the headings of views and panels
("the {shotsView} view"). Plain words that aren't a label (the concept
"dephasing", "a GHZ state") stay as words.

A translation may leave anything out, at any depth: a missing lesson, a
missing field, or a missing Help section is shown in English
(`contentText` in `i18n.js`).

## Languages

| Language | Files | Status |
|---|---|---|
| English | `locales/en.js`, `content/en.js` | Source language |
| Bahasa Indonesia (`id`) | `locales/id.js`, `content/id.js`; terms in [glossary-id.md](glossary-id.md) | Complete (interface, all 25 lessons, Concepts, Help). Translated by Claude (an AI assistant): **needs review by a physics-literate Indonesian speaker** before it is announced |
| 日本語 (`ja`) | `locales/ja.js`, `content/ja.js`; terms in [glossary-ja.md](glossary-ja.md) | Complete (interface, all 25 lessons, Concepts, Help). Translated by Claude (an AI assistant): **needs review by a physics-literate Japanese speaker** before it is announced |

Indonesian notes: one plural form (`other`), so every plural message gives
only that; numbers use a decimal comma and percentages have no space
(`0,707`, `50,0%`); lists join with "dan". Numbers inside the lesson
prose are written the Indonesian way too (`0,707² = 50%`).

Japanese notes: one plural form (`other`); numbers use a decimal point
(`0.707`, `50.0%`); lists join with 「、」 (`list.separator`) and Intl's
「または」. Japanese puts no space between sentences, so wherever the app
shows two sentences one after the other it joins them with the
`text.sentenceGap` message (`' '` in English, `''` in Japanese). "Basis
state" is 基底 rather than 基底状態, which also means "ground state". No
font change was needed: the app sets `<html lang="ja">`, so browsers pick
a Japanese font and Japanese glyph shapes for the generic sans-serif.

**Reviewing a translation.** Read it in the app (`?lang=id`, or pick it in
the top bar) next to English, and check above all that every claim about
physics is still exactly true. Change terms in the glossary first, then in
both files. `npm test` checks the structure after any change.

## Adding a language

1. Copy `locales/en.js` to `locales/<code>.js` (a
   [BCP 47](https://www.rfc-editor.org/info/bcp47) code: `de`, `pt-BR`,
   `id`) and translate the values. Keep the keys and the `{placeholders}`.
   Give each plural message the forms the language needs.
2. Copy `content/en.js` to `content/<code>.js` and translate it, keeping
   the structure, the `{placeholders}` and the order of each lesson's
   options. It can be done in parts: whatever is left out shows in English.
3. Register both in `locales/index.js` with the language's name in its own
   language (`Deutsch`, `Português (Brasil)`).
4. Run `npm test`. It checks that every language uses only English keys,
   keeps the same placeholders and markup, has exactly the plural forms its
   rules need, describes only real lessons, and keeps each lesson's number
   of options.
5. Have someone who knows the physics review the translation. Like the rest
   of the app, every translated claim must be true.

## Adding text to the app

Put every new piece of text a learner can see or hear (including
`aria-label`s, `title`s, text on canvases and screen-reader announcements)
in `locales/en.js` and use `$t` or `t`; format every number. Run the app
with `?lang=en-XA` to check nothing was missed, and `npm test` to check the
key is there and used.

### Decisions

- **Numbers inside maths** use the language's decimal separator
  (`0,707 + 0,000i`), like every other number. Decided November 2026.
- **Lesson steps name buttons** ("Press **Measure all**") with the button's
  own label, as the interface does, so a translated lesson can't name a
  button differently from the button itself. Decided November 2026; done in
  phase 3.
